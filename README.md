# Голосовой ассистент для записи в поликлинику

Голосовой ассистент для государственной поликлиники, который принимает входящие звонки пациентов, записывает на приём, отменяет записи и передаёт сложные случаи оператору. Работает полностью на локальных моделях для аудио (152-ФЗ), используя LLM в облаке только для распознавания смысла текста.

> **Хакатон:** Точка сборки 2026  
> **Заказчик:** государственная бюджетная поликлиника  
> **Целевые метрики:** доля пропущенных звонков ≤ 15%, доля неявок ≤ 12%, ≥ 60% типовых звонков без оператора, NPS ≥ 4/5

---

## Что умеет ассистент (Реализовано)

Ассистент построен на базе регламента РГ-ТЕЛ-01 и поддерживает следующие сценарии:

| Код  | Сценарий                              | Статус |
|------|---------------------------------------|--------|
| C-01 | Запись к терапевту                    | ✅ Готово |
| C-04 | Отмена записи                         | ✅ Готово |
| C-05 | Проверка статуса записи               | ✅ Готово |
| C-14 | Красный флаг (экстренная ситуация)    | ✅ Готово |
| C-15 | Жалоба (перевод на старшего админа)   | ✅ Готово |

**Ключевые особенности:**
- **Голосовой ввод и вывод:** ассистент принимает звонок (через Asterisk AudioSocket), распознаёт речь, отвечает голосом.
- **NLU на нейросети:** GigaChat понимает синонимы («к ушам горлу носу» → ЛОР), вытаскивает ФИО (включая отчество) и интенты.
- **Безопасность:** при любом признаке угрозы жизни (боль в груди, потеря сознания) диалог прерывается, пациенту рекомендуется звонить 103/112, а в МИС создаётся экстренная эскалация.

## Технологический стек

| Слой               | Технология                                              | Обоснование                                                          |
|--------------------|---------------------------------------------------------|----------------------------------------------------------------------|
| Язык и backend     | Python 3.11+, FastAPI, Pydantic v2                      | Async из коробки, строгая типизация, OpenAPI                         |
| Телефония          | Asterisk (AudioSocket)                                  | Передача аудиопотока в реальном времени                              |
| ASR                | **faster-whisper (локально)** + webrtcvad               | 152-ФЗ: аудио не покидает контур; VAD определяет конец реплики       |
| TTS                | **Silero TTS (локально)**                               | 152-ФЗ, естественное звучание, без облака                            |
| NLU и LLM          | **GigaChat (ai-sage/GigaChat3-10B-A1.8B)**              | Понимание смысла, извлечение интентов и слотов, fallback на regex    |
| Интеграции         | httpx → REST API стенда «Регистратура»                  | Async, ретраи, обработка лимита 10 req/min                           |
| Расписание         | openpyxl → Excel                                        | Контроль занятости слотов на нашей стороне                           |
| Инфраструктура     | Docker, Docker Compose                                  | Воспроизводимый запуск                                               |

## Архитектура

Проект построен по слоистой архитектуре. Зависимости направлены **сверху вниз**.

```text
┌─────────────────────────────────────────────────┐
│  Presentation Layer (API)                       │
│  app/api/, app/voice/                           │
│  - HTTP endpoints, AudioSocket                  │
│  - валидация через Pydantic-схемы               │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│  Application Layer (Services)                   │
│  app/services/                                  │
│  - Роутер диалогов (engine.py)                  │
│  - Сценарии (scenarios/)                        │
│  - NLU, красные флаги, MIS-клиент               │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│  Infrastructure Layer                           │
│  app/voice/ (ASR, TTS, AudioServer)             │
│  app/services/mis_client*.py, app/models/       │
│  - faster-whisper, Silero, httpx                │
└─────────────────────────────────────────────────┘
```

### Ключевые архитектурные решения

1. **Гибрид LLM + FSM.** GigaChat извлекает интенты, но маршрутизацию по сценариям ведёт детерминированный Python state machine. Это даёт предсказуемость, тестируемость и соответствие регламенту.
2. **Модульные сценарии.** Каждый сценарий (запись, отмена, проверка, жалоба, экстренная) изолирован в отдельном файле `app/services/dialog/scenarios/`.
3. **Голосовой pipeline.** Asterisk передаёт аудио по AudioSocket → VAD определяет конец фразы → faster-whisper распознаёт → текст уходит в `DialogEngine` → Silero TTS синтезирует ответ.
4. **152-ФЗ by design.** ASR и TTS работают полностью локально. В облако (GigaChat) уходит только текст, без голоса пациента.

## Быстрый старт

### Требования
- Docker 24+ и Docker Compose v2
- GNU Make

### Запуск

```bash
# 1. Клонировать репозиторий
git clone <url> voice_assistant_for_a_clinic
cd voice_assistant_for_a_clinic

# 2. Скопировать шаблон окружения
cp .env.example .env
# Отредактировать .env: указать MIS_TOKEN, OPENAI_API_KEY (для GigaChat)

# 3. Положить файл расписания (скачать из материалов кейса)
# data/schedule.xlsx

# 4. Поднять стек
make up

# 5. Проверить, что сервис жив
curl http://localhost:8000/health
```

- **Swagger (текстовый диалог):** http://localhost:8000/docs
- **Остановка:** `make down`

## Соответствие 152-ФЗ

- **Локальный ASR и TTS.** faster-whisper и Silero работают в контуре сервера — аудио не покидает инфраструктуру.
- **Облачный NLU.** В GigaChat уходит только текст (без голоса), и это не является персональными данными.
- **Без записи лишнего.** Аудиофайлы не сохраняются на диск после обработки.

## Тестовый стенд «Регистратура»

- **База:** `https://crm-med-mock.dbi-testing.ru/api/v1`
- **Swagger стенда:** https://crm-med-mock.dbi-testing.ru/docs

### Особенности, которые учитывает ассистент
1. Стенд не хранит расписание — контроль слотов на нашей стороне (`schedule.py`).
2. Даты — строки `ДД.ММ.ГГГГ`, дата-время — `ДД.ММ.ГГГГ ЧЧ:ММ`, GMT+4.
3. Повторная регистрация клиента → **200**.
4. `PATCH /visits` к отменённой записи → **409**.
