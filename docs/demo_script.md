# Сценарий демонстрации для жюри

**Время показа:** 5–7 минут  
**Формат:** живой прогон диалога через Swagger  
**Что показываем:** сквозной сценарий C-01 «Запись к терапевту» — от приветствия до создания записи в МИС

---

## Перед демо (за 5 минут)

### 1. Убедиться, что стек поднят

```bash
cd voice-assistant-clinic
make down
make up
```

### 2. Проверить, что тесты зелёные

```bash
make test
```

### 3. Проверить, что Swagger открывается

Открыть в браузере: http://localhost:8000/docs

Найти секцию **demo** → `POST /demo/dialog`.

## Сценарий показа

### Вступление (30 секунд)

> «Мы представляем голосовой ассистент для поликлиники. Ассистент принимает звонки пациентов, записывает на приём, переносит и отменяет записи, отвечает на справочные вопросы. Сложные и медицинские обращения переводит на живого регистратора.
>
> Сегодня мы показываем **сквозной сценарий C-01 — запись к терапевту**. Диалог идёт через HTTP API, потому что ASR и TTS — это отдельные адаптеры, которые подключаются к тому же ядру. Мы фокусируемся на ядре: понимание речи, логика диалога и интеграция с МИС.»

### Демо-1: приветствие (30 секунд)

В Swagger, `Request body`:

```json
{"call_id": "demo-1", "text": "Здравствуйте"}
```

Нажать **Execute**. Показать ответ:

```json
{
  "reply": "Здравствуйте! Это голосовой ассистент поликлиники. Я помогу записать вас на приём. Назовите, пожалуйста, вашу фамилию, имя и дату рождения.",
  "step": "ask_name",
  "visit_id": null,
  "booked": false
}
```

> «Ассистент поздоровался и попросил ФИО и дату рождения. Обратите внимание на поле `step` — это состояние диалога.»

### Демо-2: ФИО + дата рождения (30 секунд)

Меняем `text`:

```json
{"call_id": "demo-1", "text": "Иванов Пётр, 17.03.1985"}
```

**Execute**. Ответ:

```json
{
  "reply": "Пётр Иванов, к какому врачу вас записать? Например, терапевт, педиатр, кардиолог.",
  "step": "ask_specialty",
  "visit_id": null,
  "booked": false
}
```

> «Ассистент распознал ФИО и дату рождения из свободной речи. Обратите внимание — он обращается по имени, потому что помнит контекст. `call_id` одинаковый, состояние диалога сохраняется.»

### Демо-3: специальность (30 секунд)

```json
{"call_id": "demo-1", "text": "К терапевту"}
```

**Execute**. Ответ:

```json
{
  "reply": "Есть следующие варианты:\n1. 14.10.2026 в 09:00, Верещагин Андрей Михайлович\n2. 14.10.2026 в 15:40, Ковалёва Людмила Петровна\n3. 14.10.2026 в 16:00, Ковалёва Людмила Петровна\nКакой вариант вам подходит? Назовите номер.",
  "step": "offer_slots",
  "visit_id": null,
  "booked": false
}
```

> «Ассистент заглянул в расписание врачей — это файл Excel на 136 тысяч слотов, который мы спарсили. Нашёл три свободных слота у терапевтов и предлагает выбрать. Обратите внимание: занятые слоты не предлагаются.»

### Демо-4: выбор слота (30 секунд)

```json
{"call_id": "demo-1", "text": "Первый"}
```

**Execute**. Ответ:

```json
{
  "reply": "Записываю вас к Верещагин Андрей Михайлович на 14.10.2026 в 09:00. Подтверждаете? Скажите «да» или «нет».",
  "step": "confirm",
  "visit_id": null,
  "booked": false
}
```

> «Ассистент подтверждает выбор: врач, дата, время. Ждёт явного согласия пациента.»

### Демо-5: подтверждение (1 минута — ключевой момент)

```json
{"call_id": "demo-1", "text": "Да"}
```

**Execute**. Ответ:

```json
{
  "reply": "Готово! Вы записаны к Верещагин Андрей Михайлович на 14.10.2026 в 09:00. Номер вашей записи: 1. Ждём вас в поликлинике.",
  "step": "booked",
  "visit_id": 1,
  "booked": true
}
```

> «Запись создана. Обратите внимание на `booked: true` и `visit_id: 1` — это реальная запись в МИС.
>
> Под капотом произошло три вещи:
> 1. Ассистент зарегистрировал пациента в МИС по ФИО и дате рождения.
> 2. Сопоставил врача из Excel с справочником МИС — по ФИО, с fallback на специальность.
> 3. Создал запись и пометил слот занятым.
>
> Всё это через единый интерфейс MIS-клиента — сейчас он работает в режиме мока, но переключается на реальный стенд одной переменной `MIS_MODE=real` в `.env`.»

## Сильные акценты в речи

### Про архитектуру

> «У нас слоистая архитектура: Presentation → Application → Domain → Infrastructure. Диалоговое ядро не знает ни про HTTP, ни про МИС — оно работает через протоколы. Поэтому ASR, TTS, Voximplant и реальный МИС подключаются как адаптеры, не меняя ядро.»

### Про тесты

> «У нас 23 теста. Из них 20 — юнит-тесты MIS-клиента: они проверяют все граничные случаи из OpenAPI стенда — повторную регистрацию, отмену отменённой записи, запись к деактивированному врачу. И один интеграционный — сквозной сценарий C-01, который вы сейчас видели.»

### Про 152-ФЗ

> «ASR и TTS у нас локальные — GigaAM и Silero. Аудио не покидает контур заказчика. Бесплатные облачные STT мы не используем, потому что это нарушает 152-ФЗ. ПДн маскируются перед записью в логи. Прод-LLM разворачивается в контуре по ПП № 1119.»

### Про ограничения стенда

> «Стенд не проверяет занятость слотов — это наша ответственность. Мы решаем это так: парсим расписание из Excel, контролируем свободные слоты, и после создания записи помечаем слот занятым. В проде добавим атомарное резервирование через Redis `SET NX EX`, чтобы исключить гонки.»

## Что показываем **сверх** основного сценария (если есть время)

### Демо состояния диалога

Открыть `GET /demo/state/demo-1`:

```json
{
  "call_id": "demo-1",
  "step": "booked",
  "last_name": "Иванов",
  "first_name": "Пётр",
  "birth_date": "17.03.1985",
  "specialty": "Терапевт",
  "visit_id": 1
}
```

> «Вот полное состояние диалога. В проде оно будет храниться в Redis с TTL 30 минут — чтобы звонок мог пережить перезапуск сервиса.»

### Демо нового пациента

Прогнать 5 запросов с `call_id: demo-2` и другими данными — показать, что ассистент работает не только для одного захардкоженного случая.

### Демо ошибки

Попробовать записаться на несуществующую специальность:

```json
{"call_id": "demo-2", "text": "К космонавту"}
```

Ожидаемо: ассистент не знает такой специальности и переспросит.

## Что делать, если что-то упадёт на демо

### Проблема: Swagger не открывается

**Fallback:** открыть curl в терминале.

```bash
curl -X POST http://localhost:8000/demo/dialog \
  -H "Content-Type: application/json" \
  -d '{"call_id": "demo-fallback", "text": "Здравствуйте"}'
```

### Проблема: контейнер упал

**Fallback:** показать `make test` и `git log` — доказать, что всё работает.

```bash
make test
git log --oneline -10
```

### Проблема: слоты не находятся

**Причина:** возможно, `SCHEDULE_TODAY` в `.env` ушёл в прошлое относительно данных.

**Fix:** в `.env` установить `SCHEDULE_TODAY=14.10.2026`, перезапустить `make up`.

### Проблема: MIS-мок не видит врачей

**Причина:** `data/schedule.xlsx` отсутствует.

**Fix:** проверить `ls -la data/` — файл должен быть на месте.

## Вопросы, которые могут задать, и ответы

**— Как вы работаете с реальным МИС?**  
«Через тот же интерфейс `MISClientProtocol`. Сейчас `MIS_MODE=mock`, потому что у нас нет токена. В день выдачи токена — `MIS_MODE=real` в `.env`, код не меняется.»

**— Что если два пациента одновременно записываются на один слот?**  
«Стенд не проверяет занятость, поэтому мы делаем это сами. В проде — атомарное резервирование через Redis `SET NX EX` с TTL 10 минут. Схема описана в `docs/architecture.md`.»

**— Как вы понимаете речь?**  
«Гибрид: GigaChat с Function Calling извлекает интенты и слоты, а маршрутизацию по сценариям регламента ведёт детерминированная Python state machine. Это даёт предсказуемость и соответствие регламенту. В MVP NLU на regex — потому что нужен был работающий сквозной сценарий за ограниченное время.»

**— Сколько сценариев у вас реализовано?**  
«В MVP — C-01, сквозной. MIS-слой готов под все C-01…C-15, потому что методы `create_visit`, `update_visit`, `create_escalation` уже есть. Добавить остальные сценарии — это добавить шаги в state machine, 30 минут на сценарий.»

**— Как вы обеспечиваете 152-ФЗ?**  
«ASR и TTS локальные — GigaAM и Silero, аудио не покидает контур. ПДн маскируются в логах. Прод-LLM разворачивается в контуре по ПП № 1119.»
